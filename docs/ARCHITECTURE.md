# 0.10 架构

## 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `pyroller.cli` | 命令解析、stdout/stderr、进程信号 | 算法选择和候选打分 |
| `pyroller.protocol` | 请求校验、v2 事件封装、公开结果投影 | 模型、词匹配 |
| `pyroller.engine` / `config` | 稳定 Python API 与运行选项 | 实验模式暴露 |
| `pyroller.runtime` | 一首歌任务生命周期、缓存调度、产物写入 | 声学模型内部实现 |
| `pyroller.backends.catalog` | 固定模型版本、查找、下载、证据身份 | 歌词推理 |
| `pyroller.backends.whisper` / `ctc` | 神经窗口和逐帧证据 | 应用协议 |
| `pyroller.backends.separation` | 可选 Demucs 缓存与独立进程 | 自动决定使用哪种音源 |
| `pyroller.hybrid` | 纯证据算法：拼接、候选、路径选择、CTC 定时 | CLI、外部任务状态 |

`hybrid` 是 Whisper 与 CTC 混合算法的包名，不代表需要使用旧引擎。其 `AlignmentSettings`、`align_evidence`、实验定时实现和诊断对象是内部研究接口，不承诺跨版本兼容。正式 `EngineConfig` 不暴露实验参数。

## 固定流程

以下为 unordered 流程，当前默认模式为 ordered。ordered 分支保留输入行序和重复，复用同一声学证据和窗口拼接；全局加权词编辑对齐替代逐行候选发现及自由实例选择。保留两条同分回溯中一致的词对应作为定位线索（不是所有歧义的证明），已定位行复用既有 CTC 细化及粗时间回退。缺失的连续行在相邻已定位行之间联合强制对齐，按声学支持接纳；其余通过 `unaligned_lines` 输出。算法内核中的 `alignment_mode` 不改变模型缓存身份。

1. 检查 plain lyrics，创建专属输出目录；原声或显式 Demucs 人声由调用者决定。
2. FFmpeg 解码为 16 kHz 单声道；CTC 使用 4 秒核心及两侧 2 秒上下文，产生连续帧网格。
3. 释放 CTC 模型，再运行 Whisper large-v3：26 秒核心及两侧 2 秒上下文、CPU int8、beam 5、英语、无歌词提示、无历史文字条件、无 VAD。
4. 在重叠词证据中选取拼接结果；使用统一归一化和小词编辑代价发现整句候选。
5. 动态规划选择不重复占用识别词的歌词实例。歌词可以重复、跳转，未知音频可以不匹配。
6. 固定的局部 CTC 定时细化选中歌词；保留粗时间回退和歧义诊断。
7. 写入内部诊断与公开结果，发出最终快照和完成事件。

unordered 保留既有评分与定时行为，ordered 是新增的有序分支。还没有实现此前讨论的多窗词格、第二次异常窗口解码或 MLX 后端。

## 缓存与内存

语言处理由 `pyroller.language` 共用：简繁规范化、原文偏移、中文字符/英文词单位、上下文拼音及共同时间来源。中文不会按空格整句匹配，也不会因为拆成多个字就获得多份独立时间支持。

中文 Whisper 的英文子词先按原有空白重组成词，再建立匹配单位；完整精确短句即使只有一个时间来源也可提供粗定位，仍不算多个独立锚点。无法编码的行单独回退，避免使整组可编码相邻行一起放弃 CTC 细化。

Whisper 英文参数与缓存身份保持不变，中文固定 zh，混唱使用 language=None/multilingual=True（不保证逐词语言识别）。CTC 编码和帧网格由后端 codec 提供，中文使用固定 XLSR 检查点。中文帧证据仅保存本任务所需标签、blank 和全体非 blank 最大值；不重新归一化，保留当前 Viterbi 及支持判定所需信息。投影列集合和版本参与缓存身份，因此更改歌词所需标签可能导致重新计算 CTC；两种模式使用同一标签集合时仍共享证据。

默认缓存根目录仍为 `~/.cache/py-roller/v1`；这里的 v1 是既有缓存格式目录，不是产品版本或协议版本。缓存身份包含音频哈希、模型文件哈希和推理配置，切换 v3 不会误用 v2 证据。

所有模型统一存放于 `models/<kind>/<revision>/`，旧目录通过 `models migrate` 显式导入，不参与运行时查找。安装使用暂存目录及原子重命名，管理操作互斥。Demucs 固定官方检查点并通过本地仓库加载，离线运行不再要求提前生成分离缓存。详见 CLI 模型管理说明。

模型按阶段串行加载，未承诺实时流式。取消/失败不删除已完成窗口。应用应将每次任务放入独立输出目录，不要并发处理同一音源的首次 Demucs 分离；缓存分离任务使用排他锁并在冲突时失败。

## 稳定性与限制

实验性 `mul` 通过 `backends.phonemes` 将 Unicode 歌词单位映射为 eSpeak 音素，再接入同一 C++ CTC 路径计算。声学检查点固定为 `facebook/wav2vec2-xlsr-53-espeak-cv-ft`；不是把拼音交给英文字符模型。每个音素是完整词表 token，保留 token→原词/字映射，不按 IPA Unicode 字符拆分。词表外符号和不支持的发音语言显式报错，按现有粗时间/未定位机制回退。

发音语言由歌词文字和脚本分组推断，不使用 LRC 时间，也不依赖 Whisper 猜出的逐词语言。中文使用普通话 eSpeak 发音，其他脚本用文本语言识别选择可用 voice；这只是有限的语言路由，不保证识别同一文字体系内的混语、方言和多音字上下文。新增文字保留 Unicode 字母及组合符号，无空格脚本保留字符单位；Whisper 拆片来源继续共用，不生成伪独立时间。

mul 不投影词表，缓存保留所有音素列。模型及 tokenizer 哈希、G2P 版本、eSpeak 版本、语言选择和实际歌词音素映射参与缓存身份。特化 en/zh 的声学配置不因此改变。音素长度及概率支持与字母不同，现有接纳规则未重新校准；本轮固定配置验证，不逐曲调参。

内部诊断沿用历史字段名 `character_path`、`character_support`；mul 下分别表示音素标签路径和标签支持比例，不是汉字路径或汉字识别准确率。公开输出不依赖这些内部字段。

公开 JSON 使用独立的 v2 投影，避免把内部候选字段变成 Rolling Pebble 的依赖。完整快照可撤回前一版的行；同一 occurrence ID 在不同 revision 不表示同一实例。`line_id` 是归一化歌词身份，重复演唱共享它。

识别缺失、拼接损失、门槛拒绝和错误重复定位仍可能存在。CTC 支持分数不是校准置信度；不能将 `finalized`、`ctc_supported_unverified` 当作人工确认。
