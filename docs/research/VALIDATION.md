# 初版验收与 E14 人声分离对照

结论：九个主要模块已形成独立可运行的链路，E14 全曲可从未展开重复、未提供时间顺序的文本生成增量修订与 LRC。**人声分离显著改善这一首歌的结果，但当前结果仍需人工复核，不属于产品准确率验收通过。** 本轮未训练、未扫描搜索参数、未使用其他开发歌曲调参。

## 实验条件

- 歌曲：E14，deadmau5 feat. Chris James - The Veldt (8 minute edit)，解码时长 520.145625 秒。
- 输入：10 条去重、按字母排序的英文歌词；参考 LRC 含 28 次演唱，仅独立评估器读取时间戳。
- 声学模型：`facebook/wav2vec2-large-960h-lv60-self`，固定 revision `54074b1c16f4de6a5ad59affb4caa8f2ea03a119`，24 层、1024 隐藏维度、32 标签。
- 推理：M2 / 8 GB，MPS FP16、SDPA、4 秒推进、两侧各 2 秒上下文，131 个块、26007 帧。两组均无声学缓存命中。
- 搜索：同一 C++ 源码、歌词、模型文件和 `Settings`。混音及人声解码样本数完全相同，逐项核查结果保存在 `artifacts/e14-comparison.json`。
- 分离：缓存的 htdemucs，CPU 4 线程，单模型，shifts=1，overlap=0.25，随机种子 0，float32 WAV；仅保留人声文件，不裁掉间奏。

## 数量与时间

| 指标 | 原始混音 | 分离人声 |
|---|---:|---:|
| 输出演唱实例 | 6 | 25 |
| 按顺序与参考文本精确对应 | 4 / 28 | 19 / 28 |
| 文本对应且起点误差 ≤ 0.5 秒 | 4 / 28 | 18 / 28 |
| 对应实例的起点误差中位数 | 0.1625 秒 | 0.1025 秒 |
| 对应实例的起点误差 P90 | 0.2505 秒 | 0.2275 秒 |
| 对齐总耗时，不含分离 | 60.34 秒 | 40.65 秒 |
| 其中神经模型计算 | 24.48 秒 | 23.51 秒 |
| 其中搜索及恢复 | 30.05 秒 | 11.43 秒 |
| 第一条暂定输出，不含分离 | 14.44 秒 | 9.49 秒 |
| 最终标记待复核 | 1 / 6 | 6 / 25 |

分离耗时为 219.12 秒，人声路径总计算时间约 259.77 秒。首次运行预先完成全曲分离，因此首条暂定输出需要约 228.61 秒；人声已缓存时约 9.49 秒。不是实时麦克风或边分离边输出的实现。

混音版大量漏句，所以“已匹配句的误差较低”不能代表整体质量好。人声版仍有 9 个参考实例未按精确文本对应，6 个输出实例未对应，其中也可能包含 `Here, ...` 与 `..., here` 的分组差异。没有把这些差异自动认定为正确；暂不声称分组等价后的准确率。

人声版有一个对应实例误差约 -7.54 秒，其余 18 个对应实例在 0.5 秒内。例子：第一句预测 60.4525 秒，参考 60.44 秒；第二段第一句预测 330.4725 秒，参考 330.37 秒。误差针对未经逐句听辨校准的现有 LRC，不等于真实起音误差。

## 时间基准核查

这台机器安装的 Demucs 优先用 sphn 解码 MP3，而对齐器使用 FFmpeg。比较相同原始音频发现 sphn 多出 1105 个前导样本（44.1 kHz 下约 25.057 毫秒）；波形互相关在该偏移处约为 1。

第一份分离结果已保留为 `vocals.decoder-timeline.wav`，其历史跑分目录为 `e14-english-vocals-decoder-timeline`。最终对照使用仅移除解码器填充、长度匹配源 PCM 的 `vocals.wav`，重新完成了全部模型推理和搜索。这里没有使用 LRC 来估计偏移。后续分离脚本改为先用 FFmpeg 解码 PCM 再交给 Demucs，避免两种 MP3 解码时间基准混用。

## 五项架构检查

| 设计中的验证点 | 当前证据 | 判断 |
|---|---|---|
| 输入一次的歌词可多次输出 | 10 个条目生成 25 次演唱；相同条目保留不同实例 ID | 已实现，实例正确性另计 |
| 不按文本顺序演唱可重新找到位置 | 字母序输入；全曲输出恢复 19 次参考文本对应；合成测试覆盖逆序跳转 | 已实现 |
| 分块不强行切句 | 同一证据整体/分块搜索测试；另做完整 E14 模型窗口变化实验 | 搜索跨块成立；声学窗口仍有敏感性 |
| A+B 与 C 并存、可修订 | 合成声学序列同时保留两种路径；结果管理器测试将已展示两行原子替换为一行 | 已实现；声学等价时不保证唯一分组 |
| 持续输出并暴露不确定性 | 73 个事件可严格重放为最终结果，首条出现在处理音频至 74.005 秒时；6 条最终待复核 | 已实现；状态不是正确率保证 |

模型步长变为 3.6 秒时，完整输入仍为 26007 帧；输出 24 次，18 次精确文本对应参考，16 次在 0.5 秒内。与 4 秒步长输出有 19 次有序文本对应，19 次起点差异均不超过 0.36 秒。保留 4 秒默认，不根据该结果挑选最优参数。窗口变化会改变模型归一化与上下文，无法声称已达到结果不变。

另外，对人声版完整 26007 帧缓存分别一次性输入搜索器、每 137 帧输入搜索器，最终前 100 个候选快照完全一致。记录为 `e14-english-vocals/partition-check.json`。这项检查隔离了搜索器的分块行为与模型窗口变化。12 项合成测试全部通过。

## 限制与后续依据

1. 全英文初版采用字符 CTC；多语音素模型接口保留，但尚未验证多语言歌曲。此前音素模型混音试跑结果较差，而且当时搜索实现不同，不能拿它与当前人声版做单变量比较。
2. 原设计的起点是“第一个可辨认的歌词发声”。当前局部 CTC 起点只是这个目标的估计，没有经过听辨标注校准。条件区间偏窄也可能对应错误歌词。
3. 局部对齐的首尾采用简化背景状态，全球搜索的未知路径则按 CTC 新标签付费；局部模块只细化所选行附近的时间，不用该近似分数重排全局歌词身份。这是需要后续统一的近似，不能称完整概率模型已经一致。
4. `stable` 表示近期主要候选一致，错误结果仍可能稳定。本轮的 `stable_revisions` 是包含稳定行的后缀替换次数，也包括状态变化和未变行随整个后缀重发，不能当作错误确认次数。
5. 全曲分离已验证，按需局部分离、词级编辑容错、自动识别缺失歌词、语种切换与播放器接入不在本次实现中。未知路径允许不匹配音频，但不能保证歌词缺词或发音严重失真时仍找到完整行。
6. 开发集 E01/E02/E03/E04/E05/E10/E12/E14/E15/E16 只登记。本轮只计算 E14；更换模型与进行分离对照属于结构验证，不是参数调优。

实际实验文件保存在被 Git 忽略的 `artifacts/`，包括 `e14-comparison.json`、两组 `evaluation.json`、`window-sensitivity.json`、源音频及模型哈希、每一步候选和可重放的修订事件。源码与环境说明见 `README.md`。
