# E14 算法结构修改验证

本轮实现受控漏字符、分级等待、异常触发的前后句回放、自动长上下文提案和保守覆盖检查。仅使用 E14，没有开发集参数扫描。最终运行目录：`artifacts/e14-structure-v5`；旧基线：`artifacts/e14-english-vocals`。

## 已落实的结构

1. **受控漏字符**：C++ 搜索在词内允许有限的 epsilon 删除，代价明确计分。不消费音频的删除不能开始一条新歌词，首字符仍需匹配，每行预算限制省略总量和连续长度。删除立即改变词位置，从而能正确到达词边界。相邻相同 CTC 标签仍须通过 blank 分隔。未听清的位置显式保留为 -1，不伪造字符时间。
2. **分级等待**：从文本编译字符、词边界和标点提示的短语边界。对没有声学发射的长等待施加软代价；同一标签持续发射不受该罚分。短语停顿与词内卡住分开处理，不加入歌曲特定时间点。仍保留 30 秒总行长限制。
3. **前后句联合恢复**：完整候选和进度过半的部分候选都可暴露异常；异常包括长标签间隔和显式省略。检查点回放范围包含前一行，预算有冷却，结束时全量缓存复核仍保留。异常记录不是 VAD 标签，也不是已验证错误。
4. **上下文提案**：从异常自动调度最多 16 个、每个 24 秒的窗口。本轮实际 12 个。固定绝对帧网格，补算不改变帧数，重叠先加权平均，与原证据概率混合后重新搜索。目前在结束阶段执行；逐块初步结果仍正常产生。
5. **保守接纳**：不比较不同声学分布的绝对路径分数。若提案不能保留原有演唱实例的顺序、身份和约 0.5 秒起点范围，则不自动覆盖；两份路径及决定完整保留。这是阻止静默回归的措施，可能保留旧错误或拒绝合法分行变化，并不等于证明旧结果正确。
6. **结果诚实性**：发生漏字符的行强制待复核，条件时间区间为 null。该行不再用完整文本重新强制对齐，以免局部边界模块重新借用后面的声音。

默认值及调用方式见 README。C++ 原始默认接口仍可关闭这些机制，保留历史诊断脚本的严格匹配行为；正式 Python `Settings` 开启新结构。搜索中等价的未来状态只保留最佳 Viterbi 路径，不用完整的过往逐字符时刻制造多余候选；仍按省略位置保留不确定性差异。

## 完整对照

| 指标 | 原基线 | 新版本 |
|---|---:|---:|
| 输出演唱实例 | 25 | 27 |
| 参考精确文本对应 | 19 / 28 | 20 / 28 |
| 文本对应且起点误差 <= 0.5 秒 | 18 / 28 | 19 / 28 |
| 对应起点误差中位数 | 0.1025 秒 | 0.1000 秒 |
| 原来 18 个良好参考对应的保留数 | 18 | 18 |
| 显式省略字符的行 | 无此机制 | 25 / 27 |
| 待复核行 | 6 | 26 |

两个用户指出的主体句恢复，并不意味着精确 LRC 指标增加两个：161.9 秒的参考行包含尾部 Here，新输出未包含该词。保留的 18 条只证明这些已量化的对应未丢失，不代表全部内部字词、所有分组或起音都无回归。已有参考 LRC 未逐句校准。

最终接受的输出来自原始短窗声学缓存。长上下文提案没有通过覆盖检查：丢失或改变了 112.26、149.76、371.90 秒附近三个条目，因此保存为 `context-proposal.json` 供复核，没有替换当前结果。提案仍未可靠恢复最后一句。先前用人工指定区间直接替换证据能恢复最后一句，不证明当前自动调度加概率混合就能同样恢复。

耗时：360.46 秒，其中搜索约 355.31 秒；短窗 131 个块全部缓存命中，12 个长窗也全部命中，模型本次前向耗时为 0。第一条暂定结果约 12.07 秒。新结构明显比旧版慢，开销来自省略候选扩展、异常回放及两轮结束搜索。不能将缓存运行耗时当成首次模型推理时间。速度优化与触发去重仍是后续事项。

## 回归与复现

26 项测试通过，包括新增的省略位置与预算、尾部缺字符释放下一句、持续标签不误罚、缺失词尾后合法短语停顿、未知音频不硬套、同证据分块不变、补算概率归一化、不越过可见音频、补算重放不用旧检查点、前句联合回放、覆盖检查与缺字结果强制待复核。

第一次实现把漏字符与等待一起推进，不能及时跨过词边界，导致正常短语停顿被罚；后改为 epsilon 删除闭包。单纯放开所有词间等待又保留了过长跨句路径，因此最终以文本标点提供软短语提示。中间版本保留在 v2/v3/v4 目录，属于结构调试，不作为候选参数组合择优。

```sh
cmake --build src-reconstruct/build -j 4
PYTHONPATH=src-reconstruct .venv/bin/python -m unittest discover -s src-reconstruct/tests -v
.venv/bin/python src-reconstruct/run.py --audio /absolute/vocals.wav --lyrics /absolute/plain.txt --output /absolute/new-run
.venv/bin/python src-reconstruct/scripts/compare_structure.py /absolute/new-run --reference /absolute/reference.lrc
```

`--no-context-recovery` 可跳过末尾补算和第二次复核，单独验证搜索结构。原音乐库、既有人声音轨与旧 LRC 产物均未改写。

## 剩余工作

- 字符删除虽受预算限制，但实际使用频繁；需要更好的声学可信度判断，不能把所有补全都称为确实听清。
- 最后一句及弱 Here 仍未可靠恢复。本轮不继续围绕 E14 调整代价或扫描窗口。
- 当前只有删除容错，没有通用插入／替换模型；首字符不允许省略。
- blank 为主的歌唱拖腔仍可能受等待模型影响；持续标签测试不能代表所有真实拖腔。
- 分组候选可能占用同一词，跨句借音没有被数学上禁止，只是增加合理竞争与惩罚。
- 长上下文目前整份提案接纳／拒绝，尚未做到有严格边界状态验证的局部拼接，拒绝一处回归会同时拒绝其他改善。
- 基于标点的短语提示依赖歌词文本质量；无标点、多语音素等输入仍需另行验证。
