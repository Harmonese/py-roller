# 独立定时与 Whisper 歌词上下文实验

两条实验分别对照 P1/legacy；不组合新定时与提示。默认继续 robust/legacy、无提示。三首六视图复用同一音频和 CTC 缓存，参考仅进入事后评估。本轮没有逐曲调参，参考 LRC 未重新核听。

## 结果

达标为归一化文本一致、一对一实例匹配、起点误差不超过0.5秒。

## 实验一：统一背景的实例路径

实现位于 `pyroller/hybrid/joint.py`，字符路径内核仍为 C++。每实例依据自身粗时间加固定4秒上下文，最长32秒；不再按词流连续性贪心装组。

共同背景为 `max(logp(blank), max_nonblank-6)`。每个歌词路径的分数减去相同证据范围全部作背景的分数，得到替换收益。选择互不占用声音且符合实例顺序的路径，其他声音保持背景。共享背景基准避免了句间与计算块边缘采用不同规则。

A只改结构；B对短语首字符进入状态加入有上限的软时间代价，整句偏移假设固定为 -4、-2、0、2、4秒；C比较其他起点组合的分差并对边缘/歧义弃权。缩写或一对多对应按短语计一次，不把笛卡尔积当成多个独立锚点。

这是有预算的候选近似：每偏移只保留无起点限制及粗起点附近两条路径，再做实例间DP，不是对所有字符路径的精确联合最优化。区间DP目前在Python，字符动态规划在C++。超预算回退，没有实现跨32秒的边界状态传递。因而是统一目标的第一版实验，并非原计划全部细节已经完成。

### 失败原因

新结构改善了分组独立性，却不能解决背景与歌词之间的评分校准。很多真实歌词的完整字符路径分数低于背景解释：Blossom原声23句中19句、Fly原声34句中28句，保留的候选全部为非正收益。接纳C共有113个实例回退粗时间，基线仅26个。Within原声因此失去很多有效CTC修正。

背景解释较灵活，而歌词解释要求全部字符出现；音频中某些字符证据弱，累积代价就足以使整句弃权。强制完整文本的长度效应、候选只保留少量最优路径、不同实例路径互相抢占也仍存在。不能把非正收益解释为没有唱这句，更不能通过增加每句奖励把结论强行翻转。

Fly人声196.64秒一处恢复达标，但主要是回退196.78秒粗时间；不是声学路径更准确的证明。126.68秒原声问题未恢复。软先验阶段只净增一个达标实例，说明不能把这轮失败简单归咎于先验强弱。

初次运行存在全局粗时间回退影响无关实例的实现问题，已改为把粗时间展示选项纳入组合DP；保留了初次产物 `joint-context-v1`，正式定时结论来自 `joint-context-final`。没有根据歌曲改评分参数。

## 实验二：当前窗口的歌词提示

保持原定时，先使用无提示Whisper窗口，在完整plain lyrics库存里按局部顺序覆盖率检索。最多6条、192个token，以原歌词文本作为 `initial_prompt`，对相关窗口额外识别一次。库存原顺序和人工时间均不使用；不使用前一个提示结果递归检索。无相关候选时复用原窗口。

模型保持large-v2、CPU int8、4线程、beam5、temperature0、无VAD、无前窗文本条件。缓存包含歌词库存、实际提示、源窗口、模型和推理配置。上下文是模型提示而非词表约束，没有保证模型必须或不能输出某句。当前做法需要初次ASR已有部分线索，完全漏掉的内容仍可能不被检索。

### 收益和退步

- Blossom 35.67秒 `I'm well-wishing…` 两种音轨均达到参考标准，但原声原本找到的 `I was so lost…`、`I'll die…`、`We'll stay together` 消失。
- Within原声147.88秒 `Many rooms…` 达标；此前缺少的 `Where are the locks…` 也进入输出，但其起点152.22秒尚未达0.5秒标准。与此同时输出从32句减为24句，多次重复副歌省略。
- Fly原声净增2个达标，但人声从31降到21。提示不是稳定的整体改善。

粗时间达标总数也从76降到54；2秒内实例匹配从139降到115。这说明退步不能只归咎于后续CTC。原始提示窗口中可直接看到重复段省略，部分文本出现词粘连；现有窗口拼接仍可能进一步影响结果。没有逐窗人工核听，不能把所有新增内容确认为真实恢复，也不能把所有损失归为单一提示机制。

## 耗时

模型识别结束后，同机重新进行缓存算法对照：P1基线六视图3.600秒，新定时4.093秒，合计增加13.7%；其中定时部分0.037秒增加至0.507秒。逐视图总耗时变化为-3.8%、+8.6%、+28.5%、+8.6%、+14.1%、+57.0%。单次测量含运行波动，不代表各曲都满足25%目标；不包含模型或证据加载。

提示在47个窗口额外运行Whisper，新增推理1209.45秒，约20.2分钟；分曲音轨分别216.75、207.08、166.67、71.08、277.29、270.58秒。首个模型加载另计12.60秒。首次分曲实验墙钟合计约1293秒，未包含历史首轮识别与CTC计算，因此不是从音频开始的全流程总时间。正式报告目录的提示产物由该次缓存回放，`recorded_context_inference_seconds` 保留原推理耗时，不能把回放的零推理误报为免费。

## 验证与限制

57项当前测试、75项历史实验测试通过；覆盖加代价CTC与穷举对照、未知音频、实例不抢占、远处新增实例稳定性、外部背景扩展、共同时间偏移、预算退出、提示预算/检索/缓存与CLI接口。真实32秒音频完成提示CLI运行、一次预览及最终输出，额外提示推理43.40秒，总墙钟80.48秒。

结构稳定性只在列出的合成案例上验证，没有证明任意音频切块不变。起点歧义只针对有限候选集合，分差不是正确概率。现阶段不能推广任一实验为默认，也不能把本轮结果当成统一目标或歌词提示所有实现方式均无效的证明。

下一步应先重新审查背景与完整歌词的比较是否适合做存在性判定，并检查正确路径是否因单实例候选压缩而丢失；提示则需要明确保留无提示观测作为独立证据，而非整窗替换。以上是后续研究方向，本轮不追加第三条融合实验。

## 使用和产物

```bash
# 独立新定时
py-roller song.flac lyrics.txt -o output/joint --timing-mode joint
# 独立提示；保持legacy定时
py-roller song.flac lyrics.txt -o output/context --whisper-context lyrics
```

[逐实例变化与LRC](../../py-roller-artifacts/joint-context-final/summary.md)；每首 `evaluation.json` 保存配对，`windows.json` 保存实际提示与识别输出。`benchmark.json` 保存独立计时。复现脚本为 `scripts/run_joint_context.py` 与独立 `scripts/evaluate_joint_context.py`。
